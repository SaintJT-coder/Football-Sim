# Gridiron GM — integration QA audit
Date: November 3, 2026

## Scope

This round focused on actual main-branch source code for menu/save flows, prospect scouting, existing roster actions, XP safety, cross-module simulation, year rollover and persistent automated tests. It was a bug-fix and regression pass, not a new feature tier.

## Confirmed bugs and fixes committed

| Area | Problem | Change |
| --- | --- | --- |
| Legacy Combine screen | Revealed prospect true overall and ceiling before draft, conflicting with Priority 5 hidden attributes; generated a separate random combine card | Now displays only published scouting estimates, uncertainty, confidence, and already-reviewed combine results. Official Draft Combine/Pro Day remains accessible |
| Main menu | New Franchise offered only three obsolete v2 save slots even though real data uses named v3 slots | Removed old selector in the new-game flow, added a named save field, creates an independent Save Manager slot without overwriting a prior franchise |
| Legacy Roster release | Directly set player.team = -1 and bypassed contract guarantees and dead cap | Routed through GMContractsAdvanced.release / GMContractEconomy.release; player release now pays the simulated dead-cap consequence |
| Legacy free-agent signing | Signed a player without creating the advanced contract accounting record | Registers the deal in GMContractEconomy after normal cash/cap checks; does not charge the signing fee twice |
| Targeted players | Used state.players[id] as though stable IDs were always array positions | Uses string-safe lookup of the actual player ID |
| Player personality | Missing snap record with missing state could result in null.count exception in XP multiplier | Guards the snap and supplied week/year before calculating usage XP |

## Automated QA infrastructure added

.github/workflows/franchise-qa.yml runs on main-branch pushes and pull requests, checks JavaScript syntax with Node 22, and runs the following tests:

- tests/weekly-gameplan-priority3-smoke.js
- tests/contracts-priority4-smoke.js
- tests/draft-priority5-smoke.js
- tests/league-narratives-priority6-smoke.js
- tests/presentation-priority7-smoke.js
- tests/qa-menu-roster-scouting-smoke.js
- tests/full-engine-integration-smoke.js

No npm install is needed for these tests; they use Node built-ins and synthetic 32-team franchise states.

## Checks performed in this work session

- Existing Priority 3, 4, 5, 6 and 7 test scripts were executed against current source in an isolated JavaScript compatibility harness and passed.
- The new menu/roster/scouting test was executed and passed.
- A core-engine integration test passed with real franchise simulation/contract/owner/roster/personality/records/draft code. It completed a 16-game week, generated a 3-question conference, advanced into 2027 with a saved yearbook and 4% cap growth, and completed another 16-game week.
- The XP multiplier now returns a finite value with or without a supplied season state.
- Updated menu.js, franchise-integration.js, index.html inline JavaScript and affected modules were checked for parse errors.

## Limits of what was verified

The cross-module test executed in the interactive harness with four optional modules stubbed because of the tool-call limit. The committed Node integration test loads all of those modules as well and is intended to catch missing dependency/order issues in CI. A separate two-season stress test exceeded the interactive execution window, so it is not considered passed.

GitHub connector results did not expose a confirmed completed GitHub Actions run for the new workflow at the time of this audit. The workflow was committed, but its actual runner result remains to be verified through GitHub Actions.

A live browser/iPhone/iPad touch interaction test, full browser console/runtime audit, hosting/deployment verification, accessibility audit and multi-season localStorage quota/size stress test have **not** been completed. There are also remaining legacy UI modules coexisting with newer systems; changes in this pass targeted confirmed issues instead of removing legacy code wholesale.

## Recommended next QA pass

Run the workflow on GitHub Actions, inspect failures if any, and verify live pages on a real mobile viewport, especially startup/Continue, Save Manager branch loading, press room answers, roster contract actions, draft-night animation, and cross-season loading. Exercise 5–10 seasons to watch localStorage size and game performance before introducing further features.
